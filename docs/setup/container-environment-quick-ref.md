# Container Environment Setup - Quick Reference

## Summary
Ensured that all assessment containers receive a complete set of environment variables, regardless of deployment method (Fly.io, Docker script, or Docker Compose).

## What Was Fixed

### Before
- Containers were missing critical environment variables
- `.env.local` generation was incomplete
- Workspace applications couldn't access credentials properly

### After
- All containers receive 17+ environment variables
- Complete `.env.local` is generated automatically
- Workspace applications have full access to credentials and configuration

## Environment Variables Now Passed

✅ **Core Identification**
- `CANDIDATE_ID` - Primary identifier
- `CANDIDATE_UUID` - Alias for compatibility
- `SESSION_ID` - Session tracking

✅ **Supabase Credentials**
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_PRIVATE_KEY` - Schema-specific JWT
- `SUPABASE_SERVICE_ROLE_KEY` - Alias

✅ **API Proxy Configuration**
- `GEMINI_BASE_URL` - Gemini API proxy
- `GOOGLE_BASE_URL` - Google API proxy
- `GOOGLE_API_KEY` - Set to "managed-by-proxy"
- `QUARTERMASTER_API_URL` - Provisioning endpoint

✅ **Operational**
- `TELEMETRY_URL` - Telemetry endpoint
- `AUTO_COMMIT_INTERVAL` - Auto-commit frequency
- `PASSWORD` - Code-server password (empty)

## Troubleshooting

### Container starts but `.env.local` is empty
**Cause**: Environment variables not passed to container
**Fix**: Check `docker run` command or Fly.io provisioning includes all variables

### Workspace can't connect to Supabase
**Cause**: Missing or invalid Supabase credentials
**Fix**: Verify `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_PRIVATE_KEY` are set

### API calls fail with 401/403
**Cause**: Proxy URLs not configured correctly
**Fix**: Ensure `GEMINI_BASE_URL` and `GOOGLE_BASE_URL` point to proxy endpoints

### Telemetry not working
**Cause**: Missing `TELEMETRY_URL` or `SESSION_ID`
**Fix**: Both must be set for telemetry sidecar to start
